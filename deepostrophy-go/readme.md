# DEEPostrophy

ARAFATH-এর ব্যক্তিগত পোর্টফোলিও ও অ্যাপ স্টোর। সাইট তিনটি ফাইলে সাজানো — ভিজিটরের পাতা, মালিকের প্যানেল এবং দুই পাতার শেয়ার্ড লেয়ার। কোনো বিল্ড স্টেপ নেই; ফাইলগুলো সরাসরি হোস্ট করলেই চলে।

## ফাইল তালিকা

- `index.html` — শুধু ভিজিটরের পাতা: হোম, স্টোর, আইটেমের বিস্তারিত, About DEEPostrophy ও যোগাযোগ। এই পাতায় মালিক প্যানেলের কোনো লিংক, মেনু বা লগইন নেই।
- `admin.html` — শুধু মালিকের কন্ট্রোল প্যানেল: স্টোর, আইটেম, FAQ, মেসেজ, About DEEPostrophy, সাইট সেটিংস ও ডেটা। সাইটের কোনো মেনু থেকে এতে যাওয়া যায় না — ঠিকানা লিখেই খুলতে হয়।
- `shared.js` — দুই পাতার শেয়ার্ড লেয়ার: Firebase কনফিগ, ডেটা লেয়ার, রঙ, একটাই অনুবাদ-অবজেক্ট, কার্সার, ক্লিক সাউন্ড, অ্যানিমেশন ও পুরো CSS।
- `assets/cursors/` — কাস্টম কার্সারের ১৪টি ছবি (১২টি PNG + ২টি অ্যানিমেটেড APNG)।
- `firestore.rules` — Firebase Console → Firestore → Rules-এ বসানোর সিকিউরিটি নিয়ম।
- `storage.rules` — অব্যবহৃত। এই সংস্করণে ফাইল আপলোড হয় না, তাই এটি Console-এ বসানোর দরকার নেই।
- `404.html` — GitHub Pages / Netlify-এর ভাঙা লিংকের স্ট্যান্ডালোন ৪০৪ পাতা (English + বাংলা)।
- `README.md` — এই ফাইল।

তিনটি ফাইলই একই ফোল্ডারে রাখতে হবে এবং একই প্রজেক্টের একই ডেটা ব্যবহার করে — `index.html`-এ যা প্রকাশ পায়, `admin.html`-এ ঠিক সেটাই বদলানো যায়।

## মোড দুইটি

সাইট স্বয়ংক্রিয়ভাবে দুইটি অবস্থায় চলতে পারে:

1. **লোকাল মোড (ডিফল্ট)** — `shared.js`-এর `FIREBASE_CONFIG`-এ placeholder অপরিবর্তিত থাকলে সব ডেটা ব্রাউজারেই জমা থাকে। `admin.html`-এ ঢুকতে একবার নিজের একটি **লোকাল পাসকোড** সেট করবেন (অন্তত ৪ অক্ষর; সাইটের নাম বা সহজ-ধরনের পাসকোড দেবেন না)। এটি শুধু আপনার নিজের ডিভাইসে কাজ দেখার জন্য; অন্য ভিজিটর আপনার ডেটা দেখবেন না।

2. **Firebase মোড** — নিচের কনফিগ বসালে সাইট Firestore ও Firebase Auth ব্যবহার করবে (ফাইল হোস্ট আলাদা জায়গায়, সাইটে শুধু লিংক)। তখন সব ভিজিটর প্রকাশিত (published) কন্টেন্ট দেখবেন এবং শুধু মালিক (যাচাইকৃত ইমেইল) ঢুকে কন্ট্রোল প্যানেল ব্যবহার করবেন।

## Firebase চালু করা (ক্রমানুসারে)

মালিক ইমেইল সব জায়গায় একই: **`arafathhossainrifath230119@gmail.com`**। এটি ইতিমধ্যেই `shared.js`-এর `OWNER_EMAIL`, `firestore.rules` ও এই README-তে বসানো আছে। নিচের ধাপগুলো ক্রমে সম্পূর্ণ করুন।

**ধাপ ১ — Authentication চালু:** [console.firebase.google.com](https://console.firebase.google.com)-এ প্রজেক্ট খুলে **Build → Authentication → Sign-in method** → **Email/Password** Enable করুন।

**ধাপ ২ — মালিক অ্যাকাউন্ট + ইমেইল যাচাই:** **Authentication → Users** → “Add user” → ইমেইল `arafathhossainrifath230119@gmail.com` ও একটি শক্তিশালী পাসওয়ার্ড দিন। এরপর সেই Gmail-এ পাঠানো **যাচাই-লিংকে ক্লিক** করে ইমেইল verified করে নিন (যাচাই না-হলে প্যানেল খুলবে না; “আপনি মালিক নন” বার্তা দেখাবে এবং স্বয়ংক্রিয়ভাবে সাইন-আউট হয়ে যাবে — লগইন স্ক্রিন থেকে “যাচাই-লিংক আবার পাঠান” চাপা যাবে)।

**ধাপ ৩ — Firestore:** **Build → Firestore Database → Create database** (production mode), তারপর **Firestore → Rules** ট্যাবে `firestore.rules` ফাইলের পুরো কন্টেন্ট পেস্ট করে **Publish** করুন।

**ধাপ ৪ — কনফিগ:** **Project settings → Your apps → Web app** যোগ করে `apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId` কপি করুন এবং `shared.js`-এর উপরের `FIREBASE_CONFIG` ব্লকে বসান। placeholder বদলালেই সাইট স্বয়ংক্রিয়ভাবে Firebase মোডে যাবে। SDK-এর সংস্করণ ছুঁয়ে দেখবেন না — `shared.js`-এ যে সংস্করণ আছে সেটাই ঠিক।

> ⚠️ **টেস্ট মোডের নিয়ম বাদ দিন:** Firestore তৈরির সময় দেওয়া ডিফল্ট “test rules” ৩০ দিন পর সব বন্ধ করে দেয়। উপরের `firestore.rules` বসিয়ে Publish করে সেই নিয়ম সরিয়ে ফেলুন।

> ⚠️ **ভুল-ইমেইল সতর্কতা:** Firestore রুলসে ইমেইল বদলালে `shared.js`-এর `OWNER_EMAIL`-ও একইভাবে বদলাতে হবে — নাহলে লগইন বা লেখা বন্ধ হয়ে যাবে।

## ফাইল কীভাবে দেবেন

এই সাইট কোনো ফাইল আপলোড করে না — ফাইল রাখার জায়গা আলাদা, সাইটে শুধু তার **লিংক** বসে। প্রতিটি আইটেমের কভার ছবি ও ডাউনলোড একটি HTTPS লিংক; লিংকটি সরাসরি ফাইলে গেলেই চলবে। সবচেয়ে সহজ উপায় GitHub Release:

1. আপনার টুল/বই/জিপ ফাইলটি তৈরি করে নিন (যেমন `deepo-colors-1.0.zip`)।
2. GitHub-এ একটি রিপো খুলুন → **Releases → Create a new release** → ট্যাগ ও শিরোনাম দিন।
3. **“Attach binaries by dropping them here”** ঘরে ফাইলটি টেনে ছাড়ুন → **Publish release**।
4. রিলিজের Asset তালিকায় ফাইলের নামের পাশে **⬇ (download) আইকনে রাইট-ক্লিক → Copy link address** করুন। লিংকটি এমন দেখায়:
   `https://github.com/<username>/<repo>/releases/download/<tag>/<file>.zip`
5. `admin.html` খুলে **আইটেম** ট্যাব → সম্পাদনা → **ডাউনলোড লিংক** ঘরে পেস্ট করুন → **সেভ**।

একই নিয়মে কভার ছবির লিংকও — ছবিটি কোনো হোস্টে (GitHub Release, imgbb, নিজের CDN) রেখে তার সরাসরি URL বসান। লিংক না-থাকলে ডাউনলোড বোতামটি পাতায় দেখা যায় না; থাকলে বোতামে ক্লিক করলেই লিংকটি নতুন ট্যাবে খোলে। বহিঃস্থ (external) যেকোনো HTTPS লিংকও চলবে — শুধু নিশ্চিত করবেন লিংকটি সরাসরি ফাইলে যায়, কোনো লগইন দেয়াল নয়।

## GitHub Pages-এ ডেপ্লয়

1. এই ফোল্ডারের ফাইলগুলো একটি GitHub রিপো-তে পুশ করুন (`index.html`, `admin.html`, `shared.js`, `404.html`, `firestore.rules`, `assets/cursors/` — কার্সারের ছবিগুলোও সঙ্গে রাখুন)।
2. রিপো → **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / `/ (root)` → **Save**।
3. কয়েক মিনিট পর সাইট `https://<username>.github.io/<repo>/` ঠিকানায় মিলবে; প্যানেল `https://<username>.github.io/<repo>/admin.html`।
4. ৪০৪ পাতা GitHub Pages স্বয়ংক্রিয়ভাবে `/404.html` ধরে নেয়।
5. কাস্টম ডোমেইন চাইলে Pages সেকশনে ডোমেইন দিন ও রিপোতে `CNAME` ফাইল রাখুন।

> **নোট:** GitHub Pages hash-routing (`#store/...`) ভাঙে না, তাই `404.html` শুধু সত্যিকারের ভুল পাথের জন্য। SPA-র জন্য আলাদা redirect দরকার নেই।

## Netlify-তে ডেপ্লয়

**ড্র্যাগ-ড্রপ (দ্রুততম):** [app.netlify.com/drop](https://app.netlify.com/drop)-এ পুরো ফোল্ডারটি টেনে ছাড়ুন। ব্যস।

**Git থেকে:** Netlify → Add new site → Import from Git → রিপো বেছে নিন → Build command খালি রাখুন, Publish directory-তে `.` (মূল/রুট ফোল্ডার) দিন → Deploy।

**SPA redirect (ঐচ্ছিক):** একটা `netlify.toml` বানান:

```toml
[build]
  publish = "."

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

কাস্টম ডোমেইন: **Site settings → Domain management → Add custom domain**। HTTPS স্বয়ংক্রিয়।

## কন্টেন্ট ব্যবস্থাপনা (কন্ট্রোল প্যানেল)

- **স্টোর** তৈরি/সম্পাদনা/ক্রম/প্রকাশ (৮ ধরনের kind: অ্যাপ, AI টুলস, কালারফুল আর্টস, পাইথন এক্সটেনশন, বইয়ের কপি, ফাইল সংরক্ষণ, লিংক, কাস্টম)।

- **About DEEPostrophy** — এই বিভাগের লেখা। লেখাটি সাইটের About DEEPostrophy অংশেই দেখায়, অন্য কোথাও নয়; খালি রাখলে বিভাগটি খালি থাকবে।
- **সাইট সেটিংস** — সাইটের নাম, যোগাযোগের ইমেইল, হোমের পরিচয়ের লেখা (এক/দুই লাইন), সোশ্যাল লিংক।

> প্যানেলে অতিরিক্ত অ্যানিমেশন বা মোজাইক এফেক্ট চলে না — মোজাইক ও ফেড-ইন শুধু ভিজিটরের পাতায়, কার্ড ও কভার ছবিতে।

## ভাষা (৮টি — English default)

নেভবারের উপরে-ডানদিকে ভাষা-বোতামটি ছোট একটি **ড্রপডাউন** — ক্লিক করলে উপরে একটি সার্চ বাক্স, নিচে ৮টি ভাষার তালিকা (প্রতিটি নিজের লিপিতে: `English · বাংলা · Español · Deutsch · 日本語 · Français · Português · हिन्दी`, প্রতিটি সারির পাশে লাতিন সহায়ক নাম)। সার্চ বাক্সে টাইপ করলে `native`/`latin name`/`code` তিনটির মিলে ফিল্টার হয়; কোনো মিল না থাকলে "No language matches" বার্তা। বাইরে ক্লিক বা `Esc` চাপলে প্যানেল বন্ধ; পছন্দ `deeo.lang` কী-তে লিখে রাখায় রিলোডেও সেই ভাষাই চলবে। **ডিফল্ট English** (`<html lang="en">`, ফন্ট Inter; direction সব ভাষাতেই LTR)। `index.html`, `admin.html`, `404.html` — তিনটিই এই একই আচরণ মেনে চলে।

অনুবাদ আপনার হাতে: `shared.js`-এর `I18N` অবজেক্টে `list` (৮ ভাষার ক্রম + native + name), `en` (সম্পূর্ণ — বাকি সবার English fallback) এবং `bn/es/de/ja/fr/pt/hi` টেবিল। মার্কআপে লেখা সবসময় **বাংলা উৎস** (`key`), টেবিলের `value` সেই ভাষার অনুবাদ। যে ঘর খালি থাকবে — সেই লেখা **চুপচাপ ইংরেজিতে** দেখাবে; কোনো পপআপ বা প্রম্পট আসবে না। নতুন UI লেখা যোগ করার সময় শুধু `en` টেবিলে এক লাইন দিন; বাকি সব ভাষা তখন সেই লেখাটিকে English দেখাবে, পরে আপনি স্ব স্ব টেবিলে ঘর ভরে দেবেন। `404.html`-এর `STRINGS` অবজেক্টেও সেই একই নকশা (`en`/`bn` পূর্ণ, `es/de/ja/fr/pt/hi` খালি) — সেটি Firebase/shared.js-এর উপর নির্ভরশীল নয়। `{name}` / `{n}` / `{msg}` placeholder সব ভাষাতেই হুবহু একই থাকে।

অটো-ভাষা (ঐচ্ছিক): `admin.html → সাইট সেটিংস → ভাষা` বিভাগের **"অটো-ভাষা চালু"** টগল। চালু করলে এবং ভিজিটার এখনো `deeo.lang`-এ ভাষা বেয়ে না রাখলে, তাঁর ব্রাউজারের ভাষা (`navigator.language`) মিলিয়ে ৮টির মধ্যে থেকে চুপচাপ বেছে নেওয়া হবে — প্রশ্ন/পপআপ কিছুই আসবে না, ব্রাউজারে কিছু লেখাও থাকবে না (ফিরে আসার সময় আবার সিদ্ধান্ত নেবে)। ভিজিটার একবার ভাষা বেছে নিলে সেটাই স্থায়ী, অটো-নিয়ম তখন প্রযোজ্য নয়।

আপনার নিজের কন্টেন্ট (স্টোর, আইটেম, বিবরণ, FAQ-এর প্রশ্নোত্তর, About DEEPostrophy-র লেখা, সাইট সেটিংস) অনুবাদ হয় না — যেভাবে লিখেছেন সেভাবেই দেখায়, আর Flutter/Python/Firebase-এর মতো প্রযুক্তির নাম সব ভাষাতেই ইংরেজি থাকে। ফুটারের **About DEEPostrophy** লিংকটি ব্র্যান্ডের অংশ, তাই সেটিও অনুবাদ হয় না।

## লোকাল পরীক্ষা

ফোল্ডারে টার্মিনাল থাকলে:

```bash
python -m http.server 8080
# ভিজিটরের পাতা  → http://localhost:8080/index.html
# মালিকের প্যানেল → http://localhost:8080/admin.html
```

অথবা `index.html` সরাসরি ব্রাউজারে খুলুন (লোকাল মোডে)।
